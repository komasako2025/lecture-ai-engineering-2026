## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：num_train_epochs を 20 → 10 に変更（他の設定は同じ）。変更後はセッションを再起動して上から実行し直した。
- 結果（比較表や数字）：
   | | 20エポック（元の設定） | 10エポック（変更後） |
  |---|---|---|
  | 学習前 format_rate | 0.095（2/21） | 0.095（2/21） |
  | 学習後 format_rate | 1.0（21/21） | 1.0（21/21） |
  | 学習前 content_rate | 0.0（0/21） | 0.0（0/21） |
  | 学習後 content_rate | 0.952（20/21） | 0.905（19/21） |
  | 退行した質問 | なし | なし |
  | ステップ数 | 40（計算上） | 20 |
  | 最終 loss | 未記録（資料の目安は 0.01〜0.02） | 0.0999 |
  | 学習時間 | 未記録（資料の目安は 240〜290 秒） | 123 秒 |

  ※ 20エポックの loss と学習時間は、設定を変えて再実行した際に画面の表示を上書きしてしまい記録できなかった。content_rate などは、先に保存していた result.json による。資料の目安は実測値ではない。
  ※ エポックを半分にしても format_rate は 1.0 のままで、content_rate の差は1問だった。1回ずつの実験なので、この差が設定の違いによるのか学習のばらつきによるのかは判断できない。10エポックでは、担当教員への回答が「必ず与えられた FAQ に確認が必要です」とやや不自然な文になった。
- ファインチューニングが向く場面・向かない場面についての考察：
    - 向く場面：出力の形式や文体をそろえたいとき。今回は 14 件・数分の LoRA 学習で、JSON 形式の遵守率が 0.095 から 1.0 になった。プロンプトで指示しても守れない小さなモデルでも、形式を固定できた。後続のシステムが JSON を読むような、同じ形式の出力が安定して必要な場面にも向く。
  - 向かない場面：「知らないことは知らないと答える」判断を確実にさせたいとき。今回、学習後のモデルは FAQ に無い質問の一部に根拠なく断定で答えた。形式は整ったが、判断の正しさは保証されなかった。また、情報が頻繁に変わる場合は、内容が変わるたびに再学習が必要になる。
  - 今回の限界：1つのモデル、14 件の学習データ、21 問の評価、各設定1回だけの結果である。この結果から「ファインチューニングでは知識は直らない」とまでは言えず、今回のデータ・設定では判断が一部の質問で整わなかった。
